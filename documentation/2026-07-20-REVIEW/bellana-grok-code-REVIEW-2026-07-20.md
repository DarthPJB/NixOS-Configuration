## Summary
This review performed an exhaustive passive audit of nginx vhost management, dead/WIP artifacts, and Nix design anti-patterns across the fleet. **Ground 1** reveals that the "single source of truth" topology (cortex-alpha.nix) only covers the hub's 9 vhosts/proxies; the remaining ~15+ vhosts are scattered across ad-hoc `services.nginx.virtualHosts` assignments in machine configs (remote-worker, gaming-host-1), server_services (nextcloud, gitolite, klipper/fluidd, hedgedoc), and inline flake.nix overrides, with clear duplication (print-controller.johnbargman.net appears in both topology proxies and the print-controller machine's fluidd nginx). **Ground 2** identifies high-priority cleanup targets: the entire WIP two-layer stack (mk*Settings.nix + gen*.nix + core-router-topology.nix) is partially deployed yet duplicates production logic; hedgedoc.nix is completely orphaned (defined but never imported); dozens of stale plans/incidents in documentation/; and commented-out code in snippets/. **Ground 3** finds critical engineering issues: verbatim duplication of mkProxyHost/mkBaseHost logic between lib/topology/mkNginxProxies.nix (production) and genNginx.nix (WIP) violating "simplicity over cleverness" and creating divergence risk; cortex-alpha imports the WIP core-router-topology.nix while AGENTS.md and comments claim production core-router.nix is authoritative; heavy use of `pkgs.writeShellScript` (instead of writeShellApplication) and raw `"${pkgs.foo}/bin/foo"` paths (e.g. core-router.nix:66); golden tests only cover the actually-evaluated path (WIP on cortex-alpha) so production/WIP drift would be invisible; remote-worker has nginx defined in three places (machine/default.nix, nextcloud.nix, flake.nix mkX86_64 override); formatter fragility documented but unenforced at eval time. The architecture is not yet at "professional netrunner" maturity per its own AGENTS.md philosophy.

## Ground 3 — Obvious Practical Issues with Codebase, Nix Design, or Intended Design Patterns

Severity: **Bug** (definite incorrect behavior or violation of invariants), **Risk** (high chance of future breakage or silent drift), **Nit** (maintainability smell).

### Critical Duplication & Divergence Risk (Risk + Bug)
- **File: lib/topology/mkNginxProxies.nix:48-83 vs lib/topology/genNginx.nix:26-48**
  - The functions `mkProxyHost` and `mkBaseHost` are duplicated almost verbatim (proxyHeaders, websocketHeaders, isLegacyFormat, backend extraction, forceSSL/websockets defaults, listenAddrs fallback, extraConfig construction, locations."~/" shape). Comments in genNginx.nix explicitly say "Replicates production mkNginxProxies.nix output" and "Must produce byte-identical virtualHosts".
  - **Why bad**: Violates AGENTS.md "Simplicity Over Cleverness" and "Golden Tests Are Ground Truth". Any change to one must be manually mirrored or golden will only catch the path that is evaluated on the next `check-network`.
  - **Evidence**: cortex-alpha imports core-router-topology.nix (WIP path) → uses genNginx. Production core-router.nix (used in snippets and documented) uses mkNginxProxies. If a machine ever switches, output can silently differ.
  - Recommended fix: Single source. Make genNginx call the production mk* functions, or delete the WIP layer entirely until it can be proven identical via a test that evaluates both.

- **modules/core-router.nix vs modules/core-router-topology.nix (entire files)**
  - Nearly identical structure (validation, mkIf blocks for wireguard/tailscale/dns/firewall/forwarding/nginx/monitoring). Differences are only in how topology data is loaded (per-machine import + perMachineTopology wrapper in -topology variant) and nginx assignment (mkMerge vs mkOverride 100).
  - **Risk**: cortex-alpha/default.nix:23 imports the -topology variant. AGENTS.md and documentation claim the production path is active. Golden (cortex-alpha.json) reflects whatever is currently wired.
  - Recommended: Decide on one architecture. Either finish migration and delete production, or remove WIP from cortex-alpha and keep production. Do not run both.

### Serializer vs Generator Shape Inconsistency (Risk)
- **lib/serialize-config.nix:32** skips `["proxyCache" "proxyCachePath" "statusPage"]` for nginx.
- **lib/topology/genNginx.nix:85-88** returns `{ services.nginx = { enable = true; virtualHosts = ...; }; users.users.nginx.extraGroups = ...; }`
- **modules/core-router.nix:113-115** does `services.nginx.virtualHosts = lib.mkMerge [ (nginxLib.mkAllProxies { }) ];`
- **modules/core-router-topology.nix:144** does direct `= lib.mkOverride 100 ...`
- **Evidence**: dump-config + golden rely on serialize-config. If a generator starts emitting extra fields (e.g. the WIP path adds `recommended*Settings`), the serialized golden will differ from what a future production path emits.
- Recommended: Make all generators return a uniform shape that serialize-config can consume without special cases. Add a golden test that evaluates both the production transformer output and the generator output for cortex-alpha and diffs them.

### Nix Anti-Patterns (Bug / Risk)
- **Hardcoded store paths instead of lib.getExe**:
  - modules/core-router.nix:66: `ExecStart = "${pkgs.ethtool}/bin/ethtool ..."` (also duplicated in cortex-alpha/default.nix:123).
  - services/dynamic_domain_gandi.nix:36,39,42: repeated `${pkgs.lib.getExe pkgs.curl}` mixed with direct paths.
  - sysdiag.nix:43,45,69: `pkgs.writeShellScript` + `readFile`.
  - rclone-target.nix:150: `pkgs.writeShellScript "rclone-sync-...-pre"`.
  - Many game servers (minecraft-curseforge.nix:370+) correctly use `lib.getExe` + `writeShellApplication`, but the pattern is inconsistent fleet-wide.
  - **Bug**: Breaks when package changes output path; violates "closed-system" reproducibility claims.
  - Recommended: Global search/replace to `lib.getExe pkgs.ethtool` (or `lib.getExe' pkgs.ethtool "ethtool"`) + `writeShellApplication` everywhere. Add a lint rule.

- **writeShellScript instead of writeShellApplication**:
  - services/mkRunners.nix:25, github_runners.nix:13, gitlab-credentials.nix:11,39, github-runner-nixos-config.nix:23,48, sysdiag.nix (multiple), rclone-target.nix.
  - writeShellApplication provides PATH sanitization, runtimeInputs checking, and better shebang handling.
  - Recommended: Convert all. This is low-effort high-value hygiene.

- **Eval-time filesystem reads + impurity**:
  - topology/cortex-alpha.nix:523: `root = ../webroot;` (relative, becomes store path — ok).
  - But many secrix paths and `builtins.readFile ../secrets/...` in modules that are evaluated on every machine.
  - AGENTS.md emphasizes closed builds; relative paths inside the flake are fine, but the pattern of reading secrets at eval time for public keys is documented as required ("CRITICAL: WireGuard Public Keys").

- **Formatter / linter fragility (documented risk)**:
  - AGENTS.md:80-85: "DO NOT CHANGE THE FORMATTER CONFIGURATION... nixpkgs.nixpkgs-fmt ... lint-utils.linters... MUST match."
  - No CI gate or pre-commit hook visible in the tree that enforces this at contribution time. A `nix fmt` on the tree would be catastrophic if they drift.
  - Recommended: Add an explicit check in ci.nix or a flake app that runs both and fails if output differs.

### Scalability & Maintainability Smells (Nit + Risk)
- **Nginx definition locations are chaotic**:
  - Topology (only for cortex-alpha hub).
  - Direct `services.nginx = { virtualHosts = { ... }; }` in remote-worker and gaming-host-1.
  - Attribute-set mutation in nextcloud.nix:67,78 (adds to whatever the importing machine already has).
  - Inline overrides inside flake.nix mkX86_64 for remote-worker (lines 622-649).
  - Fluidd/klipper and gitolite also enable nginx.
  - No single "nginx topology" for non-hub machines. As fleet grows to 21+ machines this will become unmaintainable.
  - Recommended: Extend the topology.nginx section to all machines that need vhosts, or introduce a small `server_services/nginx-proxy.nix` pattern that all consumers import.

- **Phase discipline violation**:
  - AGENTS.md:43: "WIP code is dead code until wired into a machine's config and validated against golden."
  - enable-wg-topology.nix is wired on 13 machines (grep showed imports in terminal-*, display-*, arm-*, LINDA, alpha-*, gaming-host-1, remote-*, storage-array, print-controller, local-nas).
  - core-router-topology.nix is wired on cortex-alpha.
  - Yet the WIP nginx generator is not proven identical to production for the hub's 9 vhosts.
  - Recommended: Add explicit "this path is validated" assertions or a matrix golden test that evaluates the WIP config for every machine that has the module enabled.

- **Missing cross-machine validation for nginx**:
  - topology/validate.nix exists but only checks lan.hosts / wireguard peers / nginx backend existence against lan.hosts (tests/topology-validation.nix:93).
  - No check that a proxy backend port is actually listening on the target machine, or that two vhosts don't claim the same domain on different machines.
  - Recommended: Extend validate.nix with a "nginx vhost uniqueness" pass.
